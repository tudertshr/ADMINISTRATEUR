🏷️ VLAN — Virtual LAN

Segmentation logique du réseau pour plus de performance, sécurité et gestion

🤔 C'est quoi un VLAN ?

Un VLAN (Virtual Local Area Network) est un réseau logiqueUn réseau qui n'est pas physiquement séparé, mais isolé par configuration logicielle du switch. créé à partir d'un réseau physique. Il permet de segmenter les équipements indépendamment de leur emplacement physique.

Fa0/1 — Fa0/2
20
SALES
Fa0/3 — Fa0/4
30
MARKET
Fa0/5 — Fa0/6
99
NATIVE
Trunk Only
📡

Réduction Broadcast

Chaque VLAN = 1 domaine de broadcast. Plus de tempêtes de diffusion dans tout le réseau !

🔒

Sécurité

HR ne peut pas communiquer directement avec SALES — isolation par défaut entre VLANs !

⚡

Performance

Trafic limité au VLAN concerné → moins de congestion → meilleure bande passante !

💡 Réflexe Admin : Le Native VLAN doit être le même des deux côtés d'un trunk ! Sinon → mismatch → problème de sécurité (VLAN Hopping possible).
🎯 Mémo VLAN :
Access = 1 VLAN = 1 machine
Trunk = plusieurs VLANs = switch à switch
Native = non tagué sur trunk (VLAN 99 conseillé)

🔌 Le Trunk 802.1Q — Comment ça marche ?

Un trunk est un lien qui transporte plusieurs VLANs en même temps. Il utilise le standard IEEE 802.1Q qui ajoute un tag de 4 octets dans l'en-tête Ethernet pour identifier le VLAN.

📖 Structure d'une trame 802.1Q

Trame Ethernet normale :

[DA MAC | SA MAC | EtherType | Data | FCS]


Trame 802.1Q (avec tag inséré) :

[DA MAC | SA MAC | 0x8100 | PCP | DEI | VLAN ID (12 bits) | EtherType | Data | FCS]


💡 Le VLAN ID sur 12 bits → max 4094 VLANs possibles (1-4094, 0 et 4095 réservés)

ℹ️
Native VLAN = le seul VLAN dont les trames ne sont PAS taguées sur le trunk. Par défaut c'est VLAN 1 — on le change en VLAN 99 pour des raisons de sécurité !

🔀 Inter-VLAN Routing — Router-on-a-Stick

Par défaut, les VLANs s'ignorent ! Pour qu'ils communiquent, il faut un routeur. La méthode Router-on-a-Stick utilise un seul port physique avec des sous-interfaces (sub-interfaces).

R1 — Router-on-a-Stick Configuration
! ===== Activer l'interface physique ===== R1(config)# interface g0/0 R1(config-if)# no shutdown R1(config-if)# exit ! ===== Sous-interface VLAN 10 (HR) ===== R1(config)# interface g0/0.10 R1(config-subif)# encapsulation dot1q 10 R1(config-subif)# ip address 192.168.10.1 255.255.255.0 R1(config-subif)# exit ! ===== Sous-interface VLAN 20 (SALES) ===== R1(config)# interface g0/0.20 R1(config-subif)# encapsulation dot1q 20 R1(config-subif)# ip address 192.168.20.1 255.255.255.0 R1(config-subif)# exit ! ===== Sous-interface VLAN 30 (MARKET) ===== R1(config)# interface g0/0.30 R1(config-subif)# encapsulation dot1q 30 R1(config-subif)# ip address 192.168.30.1 255.255.255.0 R1(config-subif)# exit ! ===== VLAN 99 NATIVE (sans "native" = tagué) ===== R1(config)# interface g0/0.99 R1(config-subif)# encapsulation dot1q 99 native R1(config-subif)# ip address 192.168.90.1 255.255.255.0 R1(config-subif)# exit R1(config)# end R1# write memory
🔑 Logique : Chaque VLAN = 1 sous-interface sur le routeur. Le numéro après le point (.10, .20...) est conventionnel — il correspond au VLAN ID pour la lisibilité. Ce qui compte c'est encapsulation dot1q [ID] !

⚡ Routage inter-VLAN sur switch L3 (SVI)

En entreprise, le switch multilayer remplace souvent le routeur externe : chaque VLAN a une SVI (interface vlan X) qui sert de passerelle.

ip routing
interface vlan 10
 ip address 192.168.10.1 255.255.255.0
 no shutdown
# show ip route connected | show ip interface brief

Router-on-a-Stick = labo / PME. SVI = campus et datacenter (meilleure latence, moins de sauts).

🛡️ Sécurité VLAN

CRITIQUE 🎭 VLAN Hopping — Switch Spoofing

Un attaquant configure son PC pour se faire passer pour un switch et négocie un trunk DTP → accès à TOUS les VLANs !

FIX Désactiver DTP sur tous les ports access : switchport nonegotiate et forcer le mode access. 
# Sur TOUS les ports access :
SW(config-if)# switchport mode access
SW(config-if)# switchport nonegotiate
SW(config-if)# switchport access vlan 10
ÉLEVÉ 🏷️ Double Tagging Attack

L'attaquant envoie une trame avec 2 tags 802.1Q — le switch retire le premier tag (native VLAN) et forward le 2ème vers un autre VLAN !

FIX Changer le Native VLAN vers un VLAN inutilisé (ex: 99) et ne JAMAIS mettre des ports access sur le Native VLAN.
✅
Bonnes pratiques VLAN sécurité :
1. Changer le Native VLAN (pas VLAN 1)
2. Désactiver les ports inutilisés → shutdown + VLAN black-hole
3. Activer Port Security pour limiter les MAC addresses
4. Activer DHCP Snooping pour prévenir les faux serveurs DHCP
5. Storm-control sur les trunks : limiter broadcast/multicast/unicast inconnu
6. VLAN de management dédié (SSH uniquement depuis IP autorisées)

🌉 STP — Spanning Tree Protocol

Éviter les boucles réseau tout en gardant la redondance

🤔 Pourquoi STP existe ?

Sans STP, si tu as des liens redondants entre switches → BOUCLE INFINIE ! Les trames tournent en rond → broadcast storm → réseau down. STP résout ça en désactivant logiquement certains ports.

1
Élection
Élection du Root Bridge (BID le plus bas)
2
Assignation
Root Port, Designated Port, Blocked Port
3
Détection
BPDUs échangés, détection de boucle
4
Blocage
Port bloqué pour rompre la boucle
5
Stabilité
Réseau stable, sans boucle, avec redondance

🟢 Forwarding✅✅✅✅Normal

⏱️
Convergence STP classique ≈ 50 secondes ! (20 blocking + 15 listening + 15 learning). C'est pour ça qu'on préfère RSTP aujourd'hui qui converge en < 1 seconde !

👑 Élection du Root Bridge

Le Root Bridge est le switch central de la topologie STP. Tous les chemins actifs passent par lui. Le Root Bridge est élu via le BID (Bridge ID) le plus bas.

🔢 Structure du BID (8 octets)

BID = Priority (2 octets) + MAC Address (6 octets)


Priority par défaut : 32768

Priority = valeur configurée + VLAN ID (PVST+)

Ex: priority 32768 + VLAN 10 = BID priority 32778


⚡ À priorité égale → le plus petit MAC address gagne !

1

Tous les switches se proclament Root Bridge

Au démarrage, chaque switch envoie des BPDUs en se déclarant Root. BID = sa propre priorité + MAC.

2

Comparaison des BIDs

À réception d'un BPDU avec un meilleur BID (plus bas), le switch adopte l'autre comme Root Bridge.

3

Seul le Root Bridge envoie des BPDUs

Les autres switches ne font que relayer les BPDUs du Root Bridge vers les autres.

💡
Réflexe Admin : Tu veux contrôler qui est Root Bridge ? Configure la priorité manuellement ! Le switch core/distribution devrait TOUJOURS être Root Bridge.
spanning-tree vlan 10 priority 4096 (multiple de 4096 !)

SÉCURITÉ⚠️ BPDU Spoofing / Root Bridge Hijacking

Un attaquant peut connecter un switch avec une priorité basse → il devient Root Bridge → reconfiguration de tout STP → DoS ou man-in-the-middle !

FIX Activer BPDU Guard sur TOUS les ports access (PortFast). Si un BPDU arrive → port err-disabled immédiatement.

⚡ RSTP (802.1w) — Rapid Spanning Tree

😴 STP Classique (802.1D)

  • ⏱️ Convergence : ~50 secondes
  • 5 états de port (Blocking, Listening, Learning, Forwarding, Disabled)
  • Seulement le Root Bridge génère des BPDUs
  • Réagit lentement aux pannes

⚡ RSTP (802.1w)

  • ⚡ Convergence : < 1 seconde !
  • 3 états actifs : Discarding, Learning, Forwarding
  • Tous les switches génèrent des BPDUs (hello 2s)
  • Proposition/Accord rapide entre switches
PVST+ (Per-VLAN Spanning Tree Plus) = une instance STP PAR VLAN → tu peux avoir des Root Bridges différents par VLAN → load balancing naturel ! Cisco l'utilise par défaut avec RSTP → RPVST+
Rôle RSTPFonction
RootPort vers le Root Bridge (1 par switch)
DesignatedPort qui forward sur un segment (émet des BPDUs)
AlternateBackup du Root Port — bloqué, prêt en <1 s
BackupBackup d'un Designated sur segment partagé
⚠️
Sur les ports access : spanning-tree portfast + spanning-tree bpduguard enable (ou global spanning-tree portfast bpduguard default). Sur uplinks : spanning-tree guard root pour empêcher un switch access de devenir Root.

🔗 EtherChannel

Agrégation de liens pour plus de bande passante et redondance

🔗 C'est quoi l'EtherChannel ?

L'EtherChannel regroupe jusqu'à 8 liens physiques en un seul lien logique (Port-Channel). Résultat : plus de bande passante + redondance si un lien tombe !

SW1
Po1
4x1Gbps = 4Gbps
SW2

🔵 EtherChannel L2

  • 📍 Pour switches Access/Distribution
  • 📦 Regroupe des ports d'accès (VLANs)
  • 📡 Basé sur adresses MAC
  • 🔌 Idéal pour les trunks multi-VLAN

🟢 EtherChannel L3

  • 📍 Pour les switches Core/Distribution L3
  • 🌐 Chaque Port-Channel a une IP
  • 🚀 Basé sur adresses IP
  • 🔀 Idéal pour le routage inter-VLAN
⚠️
ATTENTION ! EtherChannel ≠ Haute Disponibilité (HA). Si le switch entier tombe, le Port-Channel tombe aussi. C'est de l'agrégation, pas de la redondance d'équipements !
✨
Avantage STP : STP voit le Port-Channel comme UN SEUL lien → pas de blocage STP sur les liens agrégés → toute la bande passante utilisée !

⚙️ LACP vs PAgP

🌍 LACP (802.3ad)

  • ✅ Standard IEEE → multi-vendor
  • 🔄 Active : initie la négociation
  • ⏳ Passive : attend la négociation
  • Active-Active ✅ | Active-Passive ✅
  • Passive-Passive ❌ (aucun n'initie)
  • Max 16 liens (8 actifs + 8 standby)

🔒 PAgP (Port Aggregation Protocol)

  • ⚠️ Propriétaire Cisco uniquement
  • 🔄 Desirable : initie la négociation
  • ⏳ Auto : attend la négociation
  • Desirable-Desirable ✅ | Desirable-Auto ✅
  • Auto-Auto ❌ (aucun n'initie)
  • Max 8 liens par Port-Channel
ProtocoleMode SW1Mode SW2Résultat
LACPActiveActive✅ EtherChannel formé
LACPActivePassive✅ EtherChannel formé
LACPPassivePassive❌ Pas d'EtherChannel
PAgPDesirableDesirable✅ EtherChannel formé
PAgPDesirableAuto✅ EtherChannel formé
PAgPAutoAuto❌ Pas d'EtherChannel
ManuelOnOn✅ Forcé (sans négociation)
Répartition de charge : un flux = même paire (MAC ou IP selon port-channel load-balance). Plusieurs flux peuvent utiliser des liens différents ; un seul gros flux ne dépasse jamais la vitesse d'un membre (ex. 1 Gbps sur Po1 à 4×1G).
🎓 Recommandation : Utilise toujours LACP — c'est le standard ! PAgP ne fonctionne qu'entre switches Cisco. Évite "On" en production car pas de vérification.

🛡️ Sécurité EtherChannel

MOYEN⚡ EtherChannel Misconfiguration Attack

Si un port EtherChannel est mal configuré, STP peut créer des loops car il voit les liens individuels au lieu du Port-Channel logique.

FIX Toujours configurer les ports membres AVANT de créer le Port-Channel. Vérifier avec show etherchannel summary — chercher le flag (P) = in Port-channel.
📌 Dans show etherchannel summary :
P = Port dans le channel ✅

D = Down ❌
s = Suspended ❌
📡 DHCP — Dynamic Host Configuration Protocol

Attribution automatique d'adresses IP via le processus DORA

🎯 Le Processus DORA

D
DISCOVER
Client cherche un serveur DHCP (broadcast)
O
OFFER
Serveur propose une adresse IP
R
REQUEST
Client accepte l'offre (broadcast)
A
ACKNOWLEDGE
Serveur confirme l'attribution

📊 Détail des messages DHCP

DISCOVER : S.IP=0.0.0.0 | D.IP=255.255.255.255 | S.MAC=Client | D.MAC=FF:FF:FF:FF:FF:FF

OFFER : S.IP=192.168.1.1 | D.IP=255.255.255.255 | S.MAC=Serveur | D.MAC=Client

REQUEST : S.IP=0.0.0.0 | D.IP=255.255.255.255 | S.MAC=Client | D.MAC=Serveur

ACK : S.IP=192.168.1.1 | D.IP=255.255.255.255 | S.MAC=Serveur | D.MAC=Client


💡 Protocole : UDP | Port serveur : 67 | Port client : 68

🤔
Pourquoi DISCOVER et REQUEST sont en broadcast ?
DISCOVER : le client ne connaît pas encore l'IP du serveur → broadcast obligatoire.
REQUEST : plusieurs serveurs peuvent avoir répondu → le client broadcaste pour que TOUS les serveurs sachent qu'il a choisi le premier qui a répondu (les autres retirent l'offre).

🛡️ Sécurité DHCP

CRITIQUE🎭 DHCP Starvation + Rogue DHCP Server

Phase 1 — Starvation : L'attaquant envoie des milliers de DISCOVER avec des MACs spoofés → le pool DHCP légitime se vide → plus d'adresses disponibles.

Phase 2 — Rogue Server : L'attaquant lance son propre serveur DHCP → distribue de fausses IPs avec lui comme gateway → Man-in-the-Middle !

FIX DHCP Snooping — le switch filtre les messages DHCP et ne permet aux réponses DHCP que sur les ports "trusted".
SW — DHCP Snooping Configuration
! ===== Activer DHCP Snooping globalement ===== SW(config)# ip dhcp snooping SW(config)# ip dhcp snooping vlan 10,20,30 ! ===== Port Trusted (vers le serveur DHCP / routeur) ===== SW(config)# interface g0/1 SW(config-if)# ip dhcp snooping trust # SEUL ce port peut envoyer des OFFER/ACK DHCP ! ===== Limiter les DISCOVER (anti-starvation) ===== SW(config)# interface range fa0/1 - 24 SW(config-if-range)# ip dhcp snooping limit rate 15 # Max 15 paquets DHCP/seconde par port — au-delà → err-disabled SW# show ip dhcp snooping binding MacAddress IpAddress Lease Type VLAN Interface 0050.7966.01 192.168.10.11 86400 dhcp-snooping 10 Fa0/1
🌍 DHCPv6 — DHCP pour IPv6

Stateful, Stateless, SLAAC — le processus SARR expliqué

🔄 Le Processus SARR (DHCPv6 Stateful)

S
SOLICIT
Client cherche un serveur DHCPv6 (multicast ff02::1:2)
A
ADVERTISE
Serveur propose ses services (Unicast/Multicast)
R
REQUEST
Client choisit un serveur et demande l'adresse
R
REPLY
Serveur envoie l'adresse IPv6 + options en Unicast
🌐
Différences vs DHCP v4 :
• DHCPv6 utilise le multicast (ff02::1:2) — pas le broadcast (IPv6 n'a pas de broadcast !)
• Ports : 546 (client) et 547 (serveur) UDP
• La Link-Local address (fe80::) est utilisée pour la communication initiale

📊 Stateful vs Stateless vs SLAAC

🔴 Stateful DHCPv6

  • ✅ Serveur gère les adresses
  • ✅ Gère aussi DNS, domaine...
  • ✅ Registre des liaisons (bindings)
  • ⚙️ Processus SARR complet
  • 🔧 Similaire au DHCPv4

🟠 Stateless DHCPv6

  • ✅ Client génère son adresse (SLAAC)
  • ✅ Serveur fournit DNS, options
  • ❌ Serveur ne gère PAS les IPs
  • ⚡ Plus léger côté serveur
  • 🔧 Flag O=1 dans le RA

🟢 SLAAC (Sans DHCP)

  • ✅ 100% autonome — pas de serveur
  • ✅ Préfixe du RA + EUI-64/Random
  • ❌ Pas de DNS automatique
  • ⚡ Très simple à déployer
  • 🔧 Flag M=0 O=0 dans le RA

🚦 Les flags du Router Advertisement (RA)

Flag M (Managed) = 1 → Utiliser DHCPv6 Stateful (M pour Managed address)

Flag O (Other) = 1 → Utiliser DHCPv6 Stateless pour les options (DNS...)

M=0, O=0 → SLAAC uniquement

M=1, O=1 → DHCPv6 Stateful complet

M=0, O=1 → SLAAC + DHCPv6 Stateless (pour DNS seulement)

IPv6 en prod : souvent SLAAC pour l'adresse + DHCPv6 stateless pour DNS. Pense aux adresses temporaires (privacy) et à la documentation des préfixes /64 par VLAN.

DNS utilise le port 53 UDP pour la plupart des requêtes (rapide). Il bascule sur TCP quand la réponse dépasse 512 octets (transferts de zone, réponses larges).

📌 Niveau pro — DNS

  • TTL : durée de cache — TTL bas = changements plus rapides, plus de charge DNS.
  • Split DNS : résolution interne (AD) vs externe (forwarders 8.8.8.8) — ne pas exposer la zone interne.
  • DNSSEC : chaîne de confiance (DS/DNSKEY) — bloque l'empoisonnement de cache si le résolveur valide.
  • Outils : nslookup, dig, show hosts — toujours tester forward et reverse (PTR) pour les serveurs.

ÉLEVÉ☠️ DNS Spoofing / Cache Poisoning

Un attaquant empoisonne le cache DNS → une requête vers "bank.com" retourne l'IP de l'attaquant → phishing !

FIX Utiliser DNSSEC pour signer cryptographiquement les réponses DNS. Configurer des timeouts de cache courts.
MOYEN🔍 DNS Tunneling

Exfiltrer des données cachées dans des requêtes DNS — difficile à détecter car DNS est rarement bloqué !

FIX Surveiller les requêtes DNS anormalement longues ou fréquentes. Utiliser un DNS Firewall.

🛡️ Sécurité Réseau

Vulnérabilités, attaques, bonnes pratiques et mitigation

⚔️ Attaques sur les Réseaux Commutés

Défense en profondeur (L2/L3) : segmentation VLAN → durcissement des ports (access + nonegotiate) → Port Security → DHCP Snooping → DAI → ACL sur L3 → SSH/AAA → logs centralisés (Syslog + NTP). Un seul contrôle ne suffit jamais.
CRITIQUE💾 MAC Address Flooding

L'attaquant inonde le switch avec des milliers de MACs faux → la table CAM se remplit → le switch ne sait plus où envoyer les trames → il les broadcast partout (fail-open) → sniffing possible !

FIX Port Security — limiter le nombre de MACs par port.
ÉLEVÉ🎭 ARP Spoofing / Poisoning

L'attaquant envoie de fausses réponses ARP → les victimes associent l'IP du routeur à la MAC de l'attaquant → tout le trafic passe par l'attaquant (MitM) !

FIX Dynamic ARP Inspection (DAI) + DHCP Snooping.
ÉLEVÉ🏷️ VLAN Hopping

Via DTP Spoofing ou Double Tagging, l'attaquant accède à des VLANs auxquels il ne devrait pas avoir accès.

FIX Désactiver DTP (switchport nonegotiate), changer le Native VLAN.
MOYEN📡 STP Manipulation

L'attaquant envoie de faux BPDUs pour devenir Root Bridge → reconfiguration de la topologie → MitM ou DoS.

FIX BPDU Guard sur tous les ports access. Root Guard sur les ports designated.

🔐 Port Security

Port Security permet de limiter le nombre d'adresses MAC autorisées sur un port de switch. Si une adresse non autorisée est détectée → action configurée (shutdown, restrict, protect).
SW — Port Security Configuration
! Port Security fonctionne UNIQUEMENT sur les ports access ! SW(config)# interface fa0/1 SW(config-if)# switchport mode access SW(config-if)# switchport port-security SW(config-if)# switchport port-security maximum 2 # Max 2 adresses MAC sur ce port ! ===== Mode de violation ===== SW(config-if)# switchport port-security violation shutdown # shutdown : port err-disabled (le plus sécurisé) ← recommandé # restrict : drop + log (garde le port up) # protect : drop silencieux (pas de log) ! ===== MAC statique ===== SW(config-if)# switchport port-security mac-address 0050.7966.6800 ! ===== MAC sticky (apprend et mémorise) ===== SW(config-if)# switchport port-security mac-address sticky # Le switch apprend les MACs connectés et les mémorise dans running-config ! ===== Vérification ===== SW# show port-security SW# show port-security interface fa0/1 SW# show port-security address ! ===== Récupérer un port err-disabled ===== SW(config-if)# shutdown SW(config-if)# no shutdown
🔑 Sticky MAC = meilleur choix pour la prod ! Le switch apprend automatiquement les MACs connectés et les protège. Plus besoin de noter toutes les MACs manuellement !

Les ACL étendues filtrent source/destination IP, protocole et ports. Appliquées in ou out sur une interface L3. Ordre séquentiel : première règle qui matche gagne.

ip access-list extended ACL-VLAN10-OUT
 permit tcp 192.168.10.0 0.0.0.255 any eq 443
 permit udp 192.168.10.0 0.0.0.255 any eq 53
 deny ip any any log
interface vlan 10
 ip access-group ACL-VLAN10-OUT in
# show access-lists | show ip interface vlan 10

Conseil : placer les règles les plus spécifiques en haut ; une ACL vide = tout refusé (implicit deny).

🎭 Scénarios de Sécurité

🔴 Scénario 1 : ARP Spoofing / MitM Attack

L'attaquant (PC Kali) est sur le même réseau que les victimes (VLAN 20 - Sales)

🖥️ Réseau : 192.168.20.0/24 | PC-Victime: .50 | Routeur: .1 | Kali: .99
⚔️ Attaquant (Kali Linux)
Exécute : arpspoof -i eth0 -t 192.168.20.50 192.168.20.1
+ arpspoof -i eth0 -t 192.168.20.1 192.168.20.50
→ La victime pense que le routeur = MAC de Kali !
📡 Trafic Capturé
Kali reçoit tout le trafic de la victime → peut lire les mots de passe HTTP, sessions non chiffrées...
🛡️ MITIGATION : Dynamic ARP Inspection (DAI)
# Activer DAI sur les VLANs concernés
SW(config)# ip arp inspection vlan 10,20,30
SW(config)# interface g0/1
SW(config-if)# ip arp inspection trust
# Le port vers le routeur est trusted
# Tous les autres ports → ARP validé contre la table DHCP Snooping
SW# show ip arp inspection vlan 20
🟠 Scénario 2 : Rogue DHCP Server

Un employé branche un routeur WiFi personnel sur le réseau → il devient serveur DHCP !

📦 PC reçoit DHCP du mauvais serveur
IP: 192.168.1.100 | Gateway: 192.168.1.1 (routeur de l'employé !)
→ L'employé peut voir tout le trafic qui passe par son routeur
🛡️ Protection DHCP Snooping
Le switch détecte un OFFER DHCP sur un port untrusted → DROP automatique ! L'employé ne peut pas distribuer d'IPs.
✅
DHCP Snooping est la première défense. Combiné avec Port Security pour empêcher la connexion non autorisée d'équipements, c'est un bouclier solide !
